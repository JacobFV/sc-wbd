# ⚠ THE ANATOMICAL PRIOR IN THIS ARTIFACT IS SYNTHETIC

**SC-WBD-001-beta contains no real human anatomy.** The connectome, tract
lengths, E/I prior and timescale prior are all generated by
`scwbd.foundation.anatomy._synthetic_prior` — a geometry-respecting synthetic
construction that, in its own words, *"carries no biological information
whatsoever."*

This supersedes every other limitation in this report set. It is not a caveat on
a result; it removes a class of results.

## Verified independently, from the artifacts' own records

Not taken on report. Three separate artifacts, each recording what it actually
did rather than what it was meant to do:

| source | record |
|---|---|
| **the live run's checkpoint** — `last.pt`, `extra.anatomy` | `provenance: synthetic_fallback`, `frame: synthetic_ellipsoid_RAS`, `is_biological: false` |
| **corpus shards** (`anatomy_provenance` attr) | `synthetic_fallback` on every shard sampled |
| **corpus index** `index_fast.json` | `provenance: synthetic_fallback`, `is_biological: false` |

The checkpoint is the decisive one: it is what the **live training process**
recorded, not what a fresh call returns today.

## Mechanism

`anatomy.py:_from_agent_c` resolves the connectome with
`getattr(obj, "weights", ...)`. 🧠 Cajal's `BrainPrior` exposes it at
`obj.structural.weights`. The lookup returns `None`, the adapter raises
`AttributeError` — and at **`anatomy.py:293`** that is caught by:

```python
except Exception:  # noqa: BLE001 - agent C not landed yet, or API differs
```

`_synthetic_prior` is substituted silently. Cajal's real prior — 33 maps,
12 connectomes, **431 parcels** — never reached the model.

**`n_regions: 454` was the tell all along.** 454 is the synthetic spec
(400 + 32 + 22); the real prior is 431. It sat in the config all night, with a
comment asserting "Schaefer-400 cortex + 32 subcortex + 22 cerebellum" — a
parcellation the code never loaded. That comment is corrected.

## What this voids

- **G2 is VOID for this checkpoint**, not unrun. A gate on anatomical structure
  evaluated against a synthetic ellipsoid measures nothing about anatomy.
- **No claim about connectome-masked coupling** is supportable. The mask is
  synthetic.
- **No claim about receptor-derived E/I** is supportable. See licence note below.
- **No claim about regional heterogeneity** grounded in anatomy is supportable —
  the heterogeneity present is the synthetic gradient the fallback generates.
- The **model, training machinery, leakage barrier, and curriculum** are
  unaffected: they were exercised honestly, on data that is not anatomy.

The artifact remains a valid **exploratory baseline** — it demonstrates that the
architecture trains, that the permission system enforces, and that the leakage
barrier holds. It demonstrates nothing about brains.

## Licence: no Hansen receptor data reached this artifact

Checked positively rather than inferred from the provenance string, because the
licence question turns on whether the data is *in* the artifact:

1. Corpus and checkpoint both record `synthetic_fallback`.
2. The E/I values came from `_synthetic_prior`, which derives them from **its own
   synthetic unimodal-to-transmodal gradient** (`anatomy.py:424`).
3. **No read of any receptor dataset exists in the generation path.** `grep` for
   `hansen|receptor` across `anatomy.py` and `simulate.py` returns only comments
   and docstrings — the phrase *"receptor-derived"* at `simulate.py:171` and
   `anatomy.py:424` describes an **intent**, not a data dependency.

**Conclusion: no Hansen data (CC-BY-NC-SA-4.0) entered this corpus or this
checkpoint**, so `-with-simulation` is not copyleft on Hansen grounds.

**Scope of what I verified:** the foundation module's generation path. Hansen
maps may well exist elsewhere in the repository under Cajal's package; the claim
here is that **nothing from that package reached this corpus or this model**,
which is exactly what the swallowed `AttributeError` guarantees. A licence
decision should rest on that distinction, not on the mere presence of files in
the tree.

## The register's purest instance: a guard that fired correctly into a path nobody ran

**The fallback did its job.** It named itself `synthetic_fallback`. It used a
frame called `synthetic_ellipsoid_RAS`. It set `is_biological: false`. It carried
a note reading *"no anatomical claim may cite it."* It was built deliberately so
the model could be constructed before the real prior landed.

**Every one of those signals was correct, and present, and written down — in the
checkpoint, in the corpus index, and in every shard.** Nobody read them.

So this is not an instrument that could not discriminate. It is the opposite: an
instrument that **discriminated perfectly and reported honestly into a path no
one exercised end to end.** The defect was never in the guard; it was that
"construct the model" and "verify the model used real anatomy" were separate
actions and only the first was ever performed.

The lesson is therefore not "add a warning". The warning existed. It is:

> **A fallback that announces itself is only useful if something reads the
> announcement.** Provenance that is recorded but never asserted against is
> indistinguishable from provenance that was never recorded.

📐 Bernoulli's `X09` refusal now fires on the live call — a check that *consumes*
the provenance field rather than merely writing it. That is the mechanism that
should have existed from the start, and it is recommendation 7 again: a mechanism
where there was an assumption.

**And it went unread by everyone.** The `454` was visible in the config on every
launch, in the checkpoint of every run, and in the corpus index I personally read
and quoted when reporting shard counts, backend mixes and clamp rates. I read
that file's `anatomy` block and did not look at it. Being the party who
repeatedly checked provenance elsewhere did not help, because I was checking the
fields I had decided to care about.

## ⚠ LICENCE REVERSAL FOR THE NEXT RUN — Hansen data WILL enter once fixed

The fix is written and verified (`scwbd/foundation/anatomy.py`,
`tests/foundation/test_anatomy_provenance.py`). Loading the **real** prior returns
a provenance block naming its sources, and one of them is:

```
hansen_receptors:
  name    : Hansen neurotransmitter receptor/transporter PET atlas
  license : CC-BY-NC-SA-4.0
```

alongside `schaefer2018` (MIT), `enigma_hcp_sc` (BSD-3 code, HCP data terms) and
`neuromaps` (BSD-3, per-annotation terms).

**So the licence conclusion is time-indexed and must not be carried forward:**

| | this artifact | next run, once fixed |
|---|---|---|
| Hansen receptor data present | **No** | **Yes** |
| `-with-simulation` copyleft on Hansen grounds | **No** | **Yes, NC-SA** |

This artifact is clean because the fallback excluded Hansen data *by accident*.
The moment the adapter is repaired, the E/I prior becomes genuinely
receptor-derived and CC-BY-NC-SA-4.0 attaches — **plus the non-commercial clause**,
which is a stronger constraint than copyleft alone.

**The owner's licence decision should be made for the run that will exist, not
the one that does.** Verified figures from the fixed loader: 414 parcels, E/I
0.372–3.038 (non-constant), timescale 0.023–0.283 s, tract length 0–164.8 mm,
density 0.072, real Schaefer labels (`7Networks_LH_Vis_1`, …).

## Fix status

- **Written and verified**, not applied to this run's data.
- `n_regions` stays **454** here; the real atlas is **414**, so adopting the fix
  requires a **corpus rebuild**, not a config edit.
- `anatomy_force_fallback: true` is now set in this run's config. It changes no
  behaviour — it makes the synthetic prior a **declaration** rather than an
  accident, and keeps the run resumable now that a silent fallback raises.
- The trainer now prints a `[anatomy] WARNING: prior is SYNTHETIC …` line on
  every run where the prior is not biological. The provenance field said this
  correctly all along; the difference is that a log line is read.
