> **The bridge has no bridge.** `scwbd.runtime` never reads a checkpoint. It
> contains no `torch.load`. The predictions `tms-robotics` consumes are

## 3. The claim boundary, structurally enforced

New module: **`scwbd/runtime/admission.py`**. Refusal happens in
`ServedModel.load`, *before the `TargetingService` is constructed*, so there is
no window in which an inadmissible checkpoint is a usable object.

### 3.1 Purposes

| purpose | mode | required conditions |
|---|---|---|
| `simulation` | computational | A0 |
| `research_offline` | computational | A0, A1 |
| `live_hardware` | live | A0 … A6 |
| `patient_directed` | live | A0 … A6 |

`simulation` asks nothing of the checkpoint. A simulation reported as a
simulation needs no artifact to be valid, and a gate that fires on simulation
is a gate everyone learns to route around. Non-required conditions are still
*evaluated and recorded* in the verdict, so it shows what was not asked rather
than hiding it.

### 3.2 Conditions

| code | condition | fires when |
|---|---|---|
| **A0** | consumer standing invariants are false | any of the three is widened |
| **A1** | claim manifest present | no `claim_manifest.json` beside the weights |
| **A2** | not an ablation control arm | manifest declares the control arm, **or says nothing** |
| **A3** | anatomy is biological | `anatomy.is_biological: false`, or unstated |
| **A4** | claim gates ran and did not fail | any `COULD_NOT_RUN`, any `FAIL`, or no gate results at all |
| **A5** | trained weights are loaded | `weights_status != "trained"` |
| **A6** | live application authorized | delegated — §3.3 |

**Every default is the refusing value.** A fact the artifact does not state is
not thereby true: a checkpoint with no anatomy record is treated as one whose
anatomy is not biological, and a checkpoint that does not say which arm it is
is treated as the control arm — because that is precisely the state run 1 was
in while claiming otherwise. Absence is not permission.

Applied to the run-1 artifact as it actually exists on disk, for any purpose
beyond `simulation`:

```
SC-WBD refuses to serve SC-WBD-001-beta for purpose 'research_offline';
1 condition(s) failed:
  - [A1] claim manifest present: no claim_manifest.json beside the checkpoint.
    An artifact that does not state its claim class cannot be checked against
    a purpose, and absence is not permission
```

Given a truthful sidecar, it fails **A2, A3, A4** simultaneously and names all
three. Tested: `test_load_time_refusal.py::TestLoadRefusesBeforeAServiceExists`
and `test_admission.py::TestRefusalsCompose`.

### 3.3 The live-application gate is Faraday's, called from here

A6 contains **no logic of its own.** It calls
`scwbd.intervene.deployment.authorize_live_application`. One implementation,
two call sites: `scwbd.intervene` gates a proposed intervention, `scwbd.runtime`
gates a checkpoint leaving for a consumer, and both ask the same predicate the
same question. Two partial gates is how a hole opens between them.

I initially built a second implementation (`LiveUseAuthorization`) and it was
wrong in a way worth recording: it introduced a **second literal
`date(2026, 8, 25)`**, which broke
`test_deployment.py::test_the_scheduled_date_appears_exactly_once_as_a_literal`.
Verified failing before the change, passing after. `admission.py` now contains
no date at all, and `LIVE_PURPOSES` is *derived* from `MODE_OF_PURPOSE` rather
than restated, so the two cannot drift.

Two properties of this call site that the intervene tests cannot cover:

- **the mode is derived from the purpose, not taken from the caller** — a
  caller cannot ask for `patient_directed` and have it checked as
  computational;
- **`as_of` is not defaulted to now.** An undated request cannot be checked
  against a dated record, and `authorize_live_application` refuses it for that
  reason (`REVIEW_TIME_UNDECLARED`). Substituting the wall clock here would
  have converted a refusal into a pass. This bit me: my first test helper
  defaulted `as_of=None` to a fixed time and hid exactly that refusal.

The date is not an unlock at this call site either:
`test_the_date_is_not_an_unlock_at_this_call_site_either` sets the clock to
2027-12-31 with a valid `AuthorizationRecord` and no review record, and asserts
the refusal stands.

### 3.4 `prospective_human` — an unconditional refusal, now satisfiable

`scwbd/runtime/provenance.py` raised on `prospective_human=True` **regardless
of any record**, with the reason "out of scope for SC-WBD-001-beta (build-order
item 6)". Both guards in that `__post_init__` carried `# pragma: no cover` and
neither was fired by any test.

This is the mirror of the stale permission strings Faraday removed, pointed the
safe way — but it made the authorization mechanism *structurally unreachable
from the consumer*, which is this brief's core deliverable. A gate that can
only ever be closed cannot discriminate, so it is not a gate.

It now routes through the same predicate and is tested in both directions:
refused with no verdict, refused on a refusing verdict (naming
`REVIEW_ABSENT`), refused on an *admitting computational* verdict, and
**permitted** on an admitting live one.

`human_use_authorized` stays unconditional, and the asymmetry is deliberate and
stated in the code: `prospective_human` is a claim about what is being
attempted, which a record can answer; `human_use_authorized` asserts that *this
repository issued* an authorization, which is never true whatever any record
says. It is now fired by a test rather than carrying a `no cover` pragma.

### 3.5 Orthogonality — stated because it will otherwise be misread

`sim2real_ready`, `promotion_eligible` and `robot_command_authority` remain
`False` **unconditionally**. They are not what this gate governs and no
authorization or review record relaxes them. An approving review of live
application is a compliance outcome, not a promotion decision; reading
"authorized" here as "promotion eligible" crosses two unrelated boundaries.
`ConsumerInvariants` refuses construction in any widened state, and
`test_admission.py::test_an_approving_review_does_not_relax_them` proves an
admitted `patient_directed` load still carries all three false.

## 4. The port contract: surviving run 2

New module: **`scwbd/runtime/ports.py`**.

### 4.1 What the checkpoint already declares

The run-1 checkpoint carries a top-level `state_layout` key that nothing in the
runtime read:

```json
{"dim": 28, "components": [
  {"name":"rate_e","dim":1,"offset":0,"units":"Hz","clock":"fast","exported":true},
  {"name":"rate_i","dim":1,"offset":1,"units":"Hz","clock":"fast","exported":true},
  {"name":"adaptation","dim":2,"offset":2,"clock":"fast","exported":false},
  {"name":"spectral","dim":16,"offset":4,"clock":"fast","exported":true},
  {"name":"hemo","dim":4,"offset":20,"clock":"slow","exported":false},
  {"name":"uncertainty","dim":4,"offset":24,"clock":"meta","exported":false}]}
```

This is a usable port declaration. It is also uniform — one layout for all 454
parcels, no family axis — and it carries `offset`, which is the trap.

### 4.2 The contract

`PortContract.from_state_layout` reads **both** shapes and refuses anything
else rather than guessing:

- `{"dim": D, "components": [...]}` — run 1. Every component becomes a port of
  the single family `all_regions`, so the homogeneity of the control arm stays
  *visible* to whoever pins the contract.
- `{"entries": [{"region": …, "component": …}]}` — region/family-indexed, the
  shape `scwbd.compiler.layout` already emits and the shape run 2 must emit.
  `region` becomes the family.

A checkpoint with no layout raises `LayoutNotDeclared`. It does **not** get an
empty contract: an empty contract reads as "this model exports nothing", which
is a far more permissive claim than "this model did not say".

### 4.3 Reads

`PortedState.read(family, name)` is the only read path. It returns a
`PortValue` carrying the declaration — units and clock travel with the numbers.
Three refusals make this structural rather than advisory:

- `RawStateAccessRefused` — `PortedState` has no `__getitem__`, no `__iter__`,
  no `__len__`, and no attribute that hands out the underlying tensor.
- `UnexportedPort` — `adaptation`, `hemo`, `uncertainty` are declared but not
  exported. Internal state is not consumer-visible merely because it shares a
  buffer.
- `UndeclaredPort` — a name the contract does not carry is an error, never an
  empty tensor and never a zero.

### 4.4 Narrowing N-1 is now enforced, not asserted

`ARCHITECTURE.md` §5b N-1 permits run 2 to pad family state to a common width,
**conditional on out-of-span reads being impossible** — "that guard is what
makes this a narrowing rather than a defect". `PortedState.read` is that guard:
a read whose declared extent exceeds the storage supplied raises
`SpanViolation` naming N-1, rather than returning padding. Heterogeneous state
cannot be passed as a single tensor at all; it must arrive as a per-family
mapping, so no family can index into another's span.

### 4.5 The pin

`PortContract.digest()` **excludes offsets**. A pure repack of the same ports is
not a contract change; a change of name, width, units, clock or export status
is. Verified in both directions
(`test_ports.py::TestTheDigestPinsTheConsumableContract`).

`ModelProvenance` now carries `port_contract_digest` and `exported_ports`, and
`ProvenanceExpectation` gained `port_contract_digest` and
`require_exported_ports`. A consumer pins the digest (whole layout) or the port
names (only what it reads). When run 2 lands, the pin fails **at load**, where
a pinned `28` would have failed silently at the first read of a component that
moved.

### 4.6 Does the current bridge reach into state by index?

**No — and that is worse than if it did.** There is no state-index reaching in
`scwbd/runtime/` because there is no state: the bridge never touches the model
(F2). The coupling to be fixed is therefore not in SC-WBD but in the consumer,
where `_rebind_head_frames` reconstructs the upstream `HeadModel` from a
hardcoded 14-field list — §6, item **C3**.

`tests/runtime/` alone: **326 tests, all passing** — 202 before this work. New

`test_load_time_refusal.py` (31).

Statement-level line trace of `scwbd/runtime/` under its own suite, after the
work (docstrings excluded): `admission.py` 86.4 %, `ports.py` 86.6 %,
`serving.py` 91.2 %, `provenance.py` 91.5 %, `targeting.py` 97.8 %. Every
refusal path in the two new modules is fired by a test; the residue is
cosmetic `__repr__`s and defensive branches on inputs the type system already
excludes. I re-traced after writing the tests specifically to find guards of my
own that had joined the class this work exists to close — there were seven

The discipline in the new tests, from `reports/decorative_guards.md`: for each
condition, (1) make it fail and assert the refusal names it by code, and (2)
make it **pass** on an input differing *only* in that condition. (2) is the
part usually missing — a gate that can never open is as useless as one that
never closes, and a suite that only exercises refusals cannot tell them apart.

One pre-existing guard fired against my own change and was right to:
`test_no_command_surface.py` flagged `ConsumerInvariants.robot_command_authority`
as an actuation-shaped symbol. Rather than widen the allow-list on trust, the
exemption is now conditional and *proved*: every excused name must be a
standing invariant that refuses construction when set true
(`test_each_excused_invariant_name_is_actually_pinned_false`). Otherwise the
exemption would itself be a way to smuggle a real command-authority flag past
the surface test by naming it after an invariant.

```python
runtime.ProvenanceExpectation(
    min_response_models=2,
```

### C3 — `_rebind_head_frames` is the fragile line (**highest breakage risk**)

`targeting.py:353-370` reconstructs the upstream `HeadModel` from a hardcoded
list of 14 named kwargs, on **every** bridge construction. If run 2's
`HeadModel` gains a field it is silently dropped and the default reapplied; if
one is renamed or removed it is a `TypeError` at construction.

**Change:** replace with a non-destructive copy that cannot drop fields:

```python
import dataclasses
head = dataclasses.replace(head_model, frames=chain)
```

`HeadModel` is a frozen dataclass upstream, so `replace` is available and is
the operation actually intended. This removes the field list entirely.

### C4 — read model quantities through ports, never through array shapes

`report.py:233-262` assumes `efield.magnitude` is one contiguous torch tensor,
that `cortex_vertices` is `(N,3)` (there is a `@ (3,3)` matmul), and that
`efield.n_elements` equals the vertex count — validated three separate times
(`support.py:743-746`, `values.py:504-510`, `field.py:97-101`). A heterogeneous
per-family layout breaks all three at once.

**Change:** consume `served.port_contract()` and read via
`PortedState.read(family, name)`. Pin `provenance.port_contract_digest` in the
handshake so a layout change is a loud failure at construction rather than a
shape error deep inside `efield_to_brain_field`.

There is **no `454` and no state-dimension constant anywhere in that
repository** — that part is already clean. The coupling is to *shape and
contiguity*, not to a magic number.

### C5 — the invariants are stored, never branched on

`claims.py:80-91` refuses to construct a widened `BridgeClaim`, which is real
and correct. But nothing anywhere reads the three flags and takes a different
path; they are carried as data into `BridgeVerdict.claim` and serialised.

Keep the construction-time refusal — it is the right shape, and SC-WBD's
`ConsumerInvariants` now mirrors it field-for-field so the two cannot drift.
Additionally, record `served.admission` in the bridge's evidence graph, and
state in `BRIDGE_CLAIM_BOUNDARY` that an approving live-application review does
**not** imply `promotion_eligible` (§3.5). Someone will otherwise read
"authorized" and conclude the opposite.

### C6 — live use needs two records, not a date

When live application is in scope, the bridge must pass a
`PreliminaryReviewRecord` **and** an `AuthorizationRecord` through to
`ServedModel.load(purpose="live_hardware", review=…, authorization=…,
as_of=…)`. Neither is sufficient alone. Nothing opens because a date passed —
that is asserted on both sides.

`sim2real_ready` and `promotion_eligible` stay `False` regardless.

### C7 — smaller couplings, worth fixing while nearby

- `targeting.py:375-387` dispatches on `type(decision).__name__` string
  equality; an upstream rename raises `TypeError`. Use `isinstance` against the

- `targeting.py:397-399` hardcodes the unresolved-quantity names

## 7. What is still open

1. **There is no path from a checkpoint to a prediction.** F2/F3. Until one
   exists, `weights_status`, the `A5` condition, and the consumer's
   `upstream_weights_status` note all describe an artifact that contributes
